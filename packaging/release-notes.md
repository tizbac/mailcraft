**MailCraft 0.14.1-rc.1 in short**: the pre-release of the work this fork carries on top of 0.14.0 — printing a message as pages, dragging mail and its files out to the desktop, Outlook `.msg` files, and Exchange server accounts' calendars, address books and to-do lists (testers welcome; sign up in [#11](https://github.com/GITHUB_REPOSITORY/issues/11))
- A message prints as pages, not as plain text: its header, formatting, tables and pictures, on the printer and the sheet you choose (File › Print).
- A message, or one of its attachments, can be dragged onto the desktop.
- Save Message As can write an Outlook `.msg` file.
- An Exchange server account keeps its calendar, address book and to-dos in step, and sends what changed a hundred items to a request.
- Outgoing mail can be Digitally signed, and OpenPGP signatures are checked in the reading pane.
- And the fixes listed below.

**What's new**
- **Printing a message, as pages.** File › Print (Ctrl+P) prints the selected message on the printer you choose: its subject, sender, recipients, date and file names, then its text with headings, bold and italic, colours, lists, quotes, rules, tables and pictures, on A4 or Letter, every page numbered at its foot. The Print dialog asks for the printer, the copies, collating, two sided and black and white, and stands over the window the message was opened in. MailCraft sets the pages itself; the system's own spooler takes them (CUPS on Linux, macOS and the BSDs, the Windows print spooler on Windows), so nothing else is opened and nothing in a message runs. A picture written into the message or attached to it is printed; one on the web is printed only if you had let pictures download and the window already has it, and one with no pictures at all prints the words that say what it is. Hidden sender text is never printed. The calendar, contacts and tasks are not printed yet, and the browser build has no printer to spool to.
- An attachment's chip can be dragged out of the reading pane or a message window onto the desktop (#626): Explorer on Windows, or a file manager on X11 or Wayland, receives the file under the name Save As gives it, marked as from the Internet.
- A message can be dragged out of the list to a folder of the desktop — Explorer on Windows, a file manager on X11 or Wayland — where it is written as the format File › Options chooses (`.eml` or `.msg`), named from its subject.
- **Save Message As writes Outlook `.msg` files.** File › Save As can save a message as a `.msg` file Outlook reads: its subject, text and HTML body, sender, To/Cc/Bcc, date, message id and header block, with one entry for each recipient and each attachment (by value, with its name, media type and content id). File › Options › Save Message As chooses whether `.eml` or `.msg` is the default; the command takes `"format": "msg"` or `"format": "eml"` to override it for one save. Reading a `.msg` file is not built yet.
- An Exchange server account sends the changes made here a hundred to a request instead of one request each, so marking tens of thousands of messages read goes up in hundreds of requests. Send/Receive Progress shows how many of them the server has taken on — a bar that moves, "Folders: 3,000 of 10,000" — instead of a spinner that says only that the run is at the folders. When a folder's answer holds a change that can't be taken in, the line now names the item by its subject when the server sent one.
- Exchange server accounts keep their calendars, address books and to-do lists in step, both ways, after the mail of a Send/Receive: appointments and meetings (including the people invited, the place, the notes and the reminder), contacts (with their addresses, phone numbers, notes and birthday) and to-dos (with their dates, importance and completion). Another person's calendar or address book can be opened by address when they have shared it, and is read with the owner's sign-in; it is listed under Shared Calendars or with the account's books. Tried against a Grommunio server; Exchange Server itself has been tried for mail and reading only.
- An Exchange server account's calendar is read a month back and a year ahead at Send/Receive, and the days you go to in the calendar beyond that are read by themselves, so they no longer stay empty until the next Send/Receive ([#1274](https://github.com/UCS-Care-Group/mailcraft/issues/1274)).
- A shared mailbox can be opened under an Exchange server account as it can under a Microsoft account: Add Shared Mailbox reads its folders and mail at its own address with the owner's sign-in, a message there can be read in full, and mail written in it is sent from its address when the server allows Send As or Send on Behalf, with the copy filed in its own Sent Items ([#70](https://github.com/GITHUB_REPOSITORY/issues/70)).
- OpenPGP Digital signatures are now checked in the reading pane; Public keys can be imported, listed and removed ([#30](https://github.com/GITHUB_REPOSITORY/issues/30)).
- Outgoing mail can be Digitally signed: Options › Sign in a new message, or Always for an account under its Digital Signatures, with an S/MIME certificate from the system's certificate store, keychain or a smartcard, or an OpenPGP key in GnuPG (a smartcard too). A message that can't be signed is held in the Outbox and never sent unsigned ([#30](https://github.com/GITHUB_REPOSITORY/issues/30)).
- The limits on importing mail files are yours to set in File › Options: the largest file (512 MB by default), the most messages from one file (200,000), and the largest and most messages of a folder of mailboxes (4 GB and 500,000), with a note on what they cost in memory.
- Linchange accounts: Add Account has a Linchange tile, and such an account takes the mail exchanger of its domain as its server. It signs in through Linchange's own page in the browser and keeps an application password named for this computer, so the account password and its second factor never go to the mail client.

**Fixes**
- An Exchange server account's folder keeps being brought up to date when its page of changes holds more read-state changes than taken in: Grommunio and Gromox send the read flags they already sent with every new page, and those are now counted apart from the messages, so a folder whose mail was read in bulk no longer stops syncing. A page that is genuinely too big says which it is — too many messages, or too many read states.
- A reminder you dismissed for an appointment or meeting of an Exchange server account stays dismissed across a Send/Receive, instead of coming back when the server gives the item a new number.
- Importing a large `.pst` file no longer holds every message's body in memory: a body, its HTML and the words the sender hid go to the mailbox's content folder as each batch is read, as attachments already did, so memory stays low while the import runs and after it finishes.
- A message saved as an Outlook `.msg` file opens in Outlook: the file is marked as a message at its root (the class Outlook looks for), its message flags are the long they are, its text is null-terminated, and its recipients and attachments say what they are.
- An appointment made in MailCraft sends only invitees a server can name: an address as `SMTP`, a directory name as `EX`, and nothing for a blank field or a bare name. A blank one made Grommunio answer that not all participants could be resolved.
- An appointment made in MailCraft now names the account as its sender (`PR_SENT_REPRESENTING_*`), so that an Exchange server keeps an organizer for it: Grommunio kept none for a plain appointment made over EWS, and its window then said the participants couldn't be resolved. A server that refuses those properties still gets the appointment, without them.
- An appointment made in MailCraft no longer disappears from its calendar on older Grommunio servers: a plain appointment now says it is not a meeting (its `PidLidAppointmentStateFlags`), a value those servers look up and fail on when it is absent, after which they leave the item out of the list.
- All-day appointments from an Exchange server account are on the right day: an event at midnight in its own time zone, which is the evening before in UTC, was shown a day early. The day is now read in the event's own zone (or this computer's when the server names none).
- Calendar tabs and the list of calendars now say whose each one is when an account's server keeps it: its name, with the account's name or address in parentheses, so two accounts' "Calendar" or a person's shared calendar can't be taken for one another.
- An Exchange server account's calendar is read again for the days in view when you move to another week or month, so appointments somebody put on the server show then instead of waiting for a full Send/Receive.
- Windows: the `.msi` now puts a MailCraft icon on the desktop, beside the Start menu entry, for everyone who uses the computer (the installer is per-machine). The Windows script and the Docker build on Linux make the same MSI.
- The check for a new version looks at this fork's releases, so a build from here is told about the updates made here.

**Public beta.** For Microsoft accounts (personal, or work or school) MailCraft is a working mail, calendar and contacts program, kept in step with Outlook on the web; keep Outlook to hand while you try it, and tell us in an issue if anything is lost or out of step. Much of what a daily mail program needs is still to come, and other kinds of account are welcome but not part of the beta. What works is in the [README](https://github.com/GITHUB_REPOSITORY#what-works-today).

MailCraft keeps your mailbox in its settings folder and saves as you go; one window per mailbox. With a Microsoft 365 or Outlook.com account you sign in on Microsoft's page, and the sign-in is kept by the system's credential store (Windows, macOS, and the Secret Service of GNOME Keyring or KWallet on Linux). What works, and how far each part is from Outlook, is in the [README](https://github.com/GITHUB_REPOSITORY#what-works-today) and in `docs/gaps.md`.

The builds are not signed with a publisher certificate yet: Windows SmartScreen and macOS Gatekeeper will ask before running them.
